# 한 줄 운동 추가 + 시간(초) 세트 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 일지에서 운동 이름·무게·횟수(또는 초)·세트 수를 한 줄로 추가하고, 운동마다 횟수 대신 시간(초)으로 기록할 수 있게 한다.

**Architecture:** 운동의 단위는 `Exercise.measure`에 저장하고, 세트에서 "횟수 또는 초" 값을 읽고 쓰는 일은 `src/workout/measure.ts` 한 곳에서 한다. 기록·채우기·정체·그래프 계산은 이 헬퍼를 거친다. 한 줄 추가의 기본값 계산은 순수 함수로 두고, UI는 `QuickAdd` 컴포넌트로 기존 `ExercisePicker`를 감싼다.

**Tech Stack:** 기존과 동일 (React 19, TS, Dexie, Vitest).

**Spec:** `docs/superpowers/specs/2026-11-15-quick-add-design.md` (상위: `2026-11-15-workout-log-design.md`)

## Global Constraints

- `Exercise.measure?: 'reps' | 'seconds'` — 값이 없으면 `'reps'`. DB 스키마·백업 `schemaVersion`은 1 유지.
- 시간 세트는 `durationSec`, 표시는 `60s`. 유산소(`cardio`)는 기존 방식(분·km) 그대로.
- 한 줄 추가는 본 세트만 만든다(워밍업 없음). 세트 수 1~20 정수.
- 같은 운동이 그날 목록에 있으면 그 블록에 세트를 이어 붙인다.
- 시간 운동은 e1RM을 계산하지 않는다.
- 기존 전역 제약(날짜는 `src/lib/date.ts`, 화면은 `repo`만, 문구 한국어) 유지.

## Review Focus

1. **횟수 기록이 있던 운동을 초로 바꾼 경우**: 옛 횟수 세트가 초로 읽히면 최고 기록·올릴 차례가 엉터리가 된다 → 세트에 있는 필드 그대로 표시하고, 계산은 현재 단위 필드만 쓴다. (Task 1 테스트)
2. **세트 수 칸에 0, 21, 2.5, 빈칸**: [추가]가 눌리면 빈 운동이나 이상한 세트가 생긴다 → 비활성. (Task 3 테스트)
3. **유산소를 한 줄 추가**: 세트 수 칸이 없고 1세트로 추가돼야 한다. (Task 3 테스트)
4. **이미 목록에 있는 운동을 다시 추가**: 블록이 두 개 생기면 지난번 요약·신기록이 갈린다 → 이어 붙이기. (Task 3 테스트)
5. **기록 없는 새 운동**: 숫자 칸 비움 + 세트 3. 무게 없이 추가해도 저장돼야 한다. (Task 2 테스트)

### Task 1: 단위 헬퍼와 계산 반영

**Files:**

- Test: `tests/workout/measure.test.ts` (+ 기존 테스트 유지)

**Interfaces:**
- Produces (`measure.ts`):
```ts
export type Measure = 'reps' | 'seconds';
export const measureOf: (ex: Pick<Exercise, 'measure'> | undefined) => Measure;   // 기본 'reps'
export function countOf(m: Measure, s: WorkoutSet): number | undefined;          // reps 또는 durationSec
export function withCount(m: Measure, s: WorkoutSet, v: number | undefined): WorkoutSet;
export const unitLabel: (m: Measure) => string;                                   // '회' | 's'
export function formatCount(s: WorkoutSet): string;                               // durationSec 있으면 '60s', 아니면 reps 숫자, 둘 다 없으면 '-'
```
- `types.ts`: `Exercise.measure?: 'reps' | 'seconds'`

규칙:
- `records.computePRs`: weight+seconds → `maxWeight`(reps 자리에 초) · `longestDuration` (maxReps·bestE1rm 없음). bodyweight+seconds → `longestDuration` · `maxAddedWeight`. 계산에는 현재 단위의 필드만 쓴다.
- `bestE1rmBefore`: 운동이 seconds면 null(호출부가 exercise를 넘기도록 시그니처를 `bestE1rmBefore(ex: Exercise, entries, date)`로 바꾼다).
- `prefill`: 올릴 차례·bodyweightReady의 value = `countOf(measure, s)`, 다음 값은 `withCount`.
- `defaultRangeFromSets(sets, settings, measure = 'reps')`: 현재 단위 값 기준.
- `status` 정체: 운동 단위로 value를 읽는다(`computeStatus`가 exercises를 모르면 세트에 `durationSec`만 있고 `reps`가 없는 세트는 durationSec을 value로 쓴다).
- `series`: `Metric`에 `'duration'` 추가, seconds 운동은 `METRICS_FOR`에서 `[{metric:'duration', label:'최장 시간'}]`. `metricsFor(ex)` 함수로 노출.
- `format.summarizeSets`: `formatCount` 사용 → `80kg × 60s,60s`, 맨몸 `60s,45s`.

### Task 2: 한 줄 추가 기본값

**Files:**
- Create: `src/workout/quickAdd.ts`
- Test: `tests/workout/quickAdd.test.ts`

**Interfaces:**
- Consumes: `measureOf`, `countOf`, `withCount` (Task 1)
- Produces:
```ts
export interface QuickValues { weightKg?: number; count?: number; setCount: number; durationMin?: number; distanceKm?: number }
export function quickDefaults(ex: Exercise, entries: Entry[], date: ISODate): QuickValues;
export function buildQuickSets(ex: Exercise, v: QuickValues): WorkoutSet[];
export const isValidSetCount: (n: number | undefined) => boolean;   // 정수 1~20
```
규칙: `quickDefaults` = `date` 이전·비삭제·비디로드의 가장 최근 그 운동 본 세트들 → weight 운동은 마지막 본 세트 `weightKg`, bodyweight는 `addedWeightKg`를 `weightKg` 자리로; count = 마지막 본 세트 `countOf`; setCount = 본 세트 수. 기록 없으면 `{ setCount: 3 }`. cardio는 마지막 세트의 분·km, setCount 1. `buildQuickSets`: weight → `{isWarmup:false, weightKg, ...withCount}` × setCount, bodyweight → `addedWeightKg`, cardio → `{durationSec: min*60, distanceKm}` 1개.

### Task 3: 한 줄 추가 UI와 단위 전환 UI

**Files:**
- Create: `src/ui/entry/QuickAdd.tsx`
- Modify: `src/ui/entry/EntryModal.tsx` (ExercisePicker → QuickAdd, 이어 붙이기), `src/ui/entry/SetRow.tsx` + `ExerciseBlock.tsx` (단위 버튼, 시간 칸), `src/ui/exercise/ExerciseForm.tsx` (단위 선택), `src/ui/routines/RoutineEditor.tsx` (단위 표시), `src/ui/records/RecordsScreen.tsx`·`ExerciseDetail.tsx` (최장 시간, metricsFor), `src/ui/styles.css`
- Test: `tests/ui/quickAdd.test.tsx` (+ 기존 UI 테스트 갱신)

**Interfaces:**
- Consumes: Task 1, Task 2, `ExercisePicker`, `repo.saveExercise`
- Produces: `QuickAdd({ date: ISODate; entries: Entry[]; onAdd(ex: Exercise, sets: WorkoutSet[]): void })`

규칙:
- QuickAdd: 운동이 안 골라졌으면 `ExercisePicker`만 보인다. 고르면 `[이름 ✕] [무게]kg [횟수][회|s] [세트]세트 [추가]` + 지난번 요약. 라벨: `무게`, `추가 무게`, `횟수`/`시간(초)`, `세트 수`, cardio는 `시간(분)`, `거리(km)`. [추가]는 `isValidSetCount` 거짓이면 disabled. 추가 후 처음 상태로.
- 단위 버튼(`회`/`s`, aria-label `단위 바꾸기`)은 `repo.saveExercise({...ex, measure})`로 운동에 저장하고 QuickAdd 숫자와 SetRow 라벨이 바로 바뀐다.
- EntryModal `onAdd`: 같은 exerciseId 블록이 있으면 sets 뒤에 이어 붙이고, 없으면 새 블록. 세트 변경이므로 확정(dirty) 처리.
- SetRow: seconds 운동은 `횟수` 칸 대신 `시간(초)` 칸(단위 표시 `s`), `+1회` 대신 `+5s`.
- ExerciseForm: 무게·맨몸일 때 "횟수 / 시간(초)" 선택(aria-label `세는 방식`).
- RoutineEditor: seconds 운동의 범위 뒤 단위 `s`.
- Records: PR 줄에 `최장 시간 60s`, maxWeight는 `20kg × 60s`.
