# 운동일지 PWA 설계 문서

- 작성일: 2026-11-15
- 상태: 초안 (사용자 승인 전)

## 1. 목적과 배경

메모장에 운동을 적어 두고 점진적 과부하에 맞춰 무게·횟수를 바꿔 가며 기록하던 것을, 아이폰에 설치한 PWA 일지로 옮긴다.

사용자의 운동 방식:
- **3분할**(예: 가슴·삼두 / 등·이두 / 하체·어깨), **3일 운동 + 1일 휴식**
- **고중량 / 저중량을 바퀴마다 번갈아** 한다. 저중량은 1RM의 약 70%이고, 횟수를 많이 가져가지 않는다.
- 한 바퀴 = 8일 (고중량 3일 + 휴식 + 저중량 3일 + 휴식). 요일과 맞지 않는다.
- 운동 순서는 거의 고정이다.
- 맨몸 운동을 하고, 유산소는 가끔 한다.
- 기기는 아이폰.

이 앱의 핵심 가치는 **메모장보다 빠른 기록**과 **이 사용자의 분할·강도 순환을 앱이 이해하는 것**이다.

## 2. 목표 / 비목표 / 실패 조건

**목표 (1차 버전)**
- 달력 일지 + 날짜별 자유 메모
- 운동 세 종류(무게 / 맨몸 / 유산소) 칸 입력
- 루틴: 일지에서 등록, 별도 화면에서 순서·내용 관리, 휴식 포함, 다음 차례 알려주기
- 루틴을 고르면 지난번 같은 루틴 기록으로 세트를 미리 채움
- 운동별 증가 단위 + 목표 횟수 범위 기반 "무게 올릴 차례" 추천
- 최고 기록 화면, 추정 1RM, 그래프, 신기록 🏆 표시
- 운동 이름 자동완성, 검색
- 운동별 고정 메모, 워밍업 세트 표시, 루틴 건너뛰기
- 디로드 (바퀴 주기 + 정체 신호 추천 + 직접 켜기)
- 운동마다 부위 정보 저장 (볼륨 화면은 2차)
- JSON 백업 내보내기/가져오기, 백업 알림, 홈 화면 추가 안내
- 나중에 서버 동기화를 붙일 수 있는 데이터 구조

**비목표 (이번에 안 함)**
- 서버, 로그인, 여러 기기 동기화
- 애플 워치·건강 앱 연동, 푸시 알림
- 휴식 타이머, 부위별 볼륨 화면, 체중 기록, 세트별 RPE (2차 후보)
- 메모장 기록 가져오기(변환 기능). 사용자가 최근 한 바퀴 정도를 달력에서 직접 입력한다. 지난 날짜도 오늘과 똑같이 입력할 수 있으면 된다.

**실패 조건 (동작해도 실패로 보는 것)**
- 입력이 메모장보다 느리거나 번거로움
- 기록 데이터가 사라짐
- 앱이 사용자의 숫자를 마음대로 바꿈 — 앱은 **미리 채우고 추천만** 하고, 모든 숫자는 사용자가 고칠 수 있어야 한다.

## 3. 제약

- 데이터는 기기(IndexedDB)에만 저장한다. 서버로 아무것도 보내지 않는다.
- iOS Safari PWA: 홈 화면에 추가해야 저장소가 안정적으로 유지된다. 백그라운드 알림·타이머는 신뢰할 수 없다.
- HTTPS 배포가 필요하다 → 개인 GitHub 계정(crebits)의 GitHub Pages. 회사 저장소와 분리한다.
- 프로젝트 폴더: `~/workspace/workout-log`

## 4. 방법 비교 (선택 완료)

| | 구성 | 장점 | 단점 |
|---|---|---|---|
| **A (선택)** | Vite + React + TypeScript, IndexedDB(Dexie), vite-plugin-pwa | 화면이 많은 앱에 알맞음. 기록이 쌓여도 검색·집계가 빠름. 오프라인 캐시 자동 처리 | 빌드 도구 필요 |
| B | Next.js 정적 내보내기 | 회사에서 쓰는 도구라 익숙함 | 서버 기능이 필요 없는 앱에 무겁고 PWA 설정이 번거로움 |
| C | 빌드 없는 HTML/JS + localStorage | 가장 단순 | 기능이 많아지면 관리가 어렵고, localStorage 용량(약 5MB)과 검색 성능 한계 |

사용자가 A를 골랐다. 나중에 서비스로 만들면 A에 **별도 서버를 붙여 동기화만 추가**하는 방향이다.

## 5. 화면 구성

### 5.1 달력 (첫 화면)
- 월 달력. 날짜 칸에 그날 루틴 이름을 작게 표시(휴식은 휴식으로, 디로드는 구분 표시).
- 위쪽 안내 줄 (해당할 때만):
  - **다음 차례**: "다음: 하체·어깨 고중량" 또는 "오늘은 휴식 차례"
  - **디로드 알림**: 주기 도달 또는 정체 신호
  - **백업 알림**: 마지막 백업 후 설정한 기간(기본 14일) 경과
- 날짜를 누르면 일지 모달이 열린다.
- 아래 탭: 달력 / 최고 기록 / 루틴 / 검색 / 설정 (배치는 구현 시 결정)

### 5.2 일지 모달 (날짜별)

```
┌ 11월 14일 (금) ─────────────── ✕ ┐
│ 루틴: [가슴·삼두 고중량 ▾]  ⭐등록  │
│ [디로드 □]                          │
│                                     │
│ 벤치프레스  📌 의자 4, 그립 넓게    │  ← 운동별 고정 메모
│  지난번: 80kg × 8,8,8  ⬆ 무게 올릴 차례│
│  W  [40]kg [10]회                   │  ← 워밍업 세트
│  1  [82.5]kg [6]회  [+단위][+1회]   │
│  2  [82.5]kg [6]회                  │
│  [+ 세트]                           │
│ [+ 운동 추가 (자동완성)]            │
│ 메모: [컨디션 좋음...           ]   │
│              [그대로 완료]          │
└─────────────────────────────────────┘
```

- **루틴 선택**: 고르면 루틴의 운동을 순서대로 넣고 세트를 미리 채운다(6장). 루틴 없이 운동을 하나씩 추가해도 된다. 다음 차례 루틴이 기본으로 선택되어 있다.
- **휴식 기록**: 루틴 목록에서 "휴식"을 고를 수 있다.
- **⭐ 루틴 등록**: 지금 일지의 운동 구성을 새 루틴으로 저장하거나, 선택된 루틴을 지금 구성으로 덮어쓴다(덮어쓰기는 확인 후).
- 운동 순서는 그날만 바꿀 수 있다(일지에만 반영, 루틴은 그대로).
- 지난번 같은 루틴의 기록을 운동 옆에 작게 계속 보여준다.
- 세트마다 워밍업 표시를 켜고 끌 수 있다.
- 증가 버튼: 무게 운동은 `+{운동별 증가 단위}`와 `+1회`, 맨몸 운동은 `+1회`.
- **자동 저장** [Claude 판단]: 저장 버튼 없이 바뀔 때마다 바로 저장한다. 운동 중 세트마다 적다가 모달을 닫거나 iOS가 앱을 종료해도 잃지 않게 하기 위해서다.
  - 루틴을 골라 미리 채우기만 하고 아무것도 고치지 않으면 저장하지 않는다(그 날은 기록 안 한 날). 미리 채운 숫자 그대로 했다면 [그대로 완료]를 눌러 저장한다.
- 기록이 저장될 때 신기록이 있으면 🏆 표시.

### 5.3 루틴 관리
- 루틴 목록을 끌어서 순서를 바꾼다. 목록은 순환한다(마지막 다음은 처음).
- "휴식" 항목을 목록 어디든 끼워 넣을 수 있다.
- 루틴을 열면 운동 목록을 끌어서 순서를 바꾸고, 운동마다 **목표 횟수 범위**를 정한다.

```
┌ 루틴 ───────────────────────────┐
│ ≡ 1. 가슴·삼두 고중량    ✎       │
│ ≡ 2. 등·이두 고중량      ✎       │
│ ≡ 3. 하체·어깨 고중량    ✎       │
│ ≡ 4. 휴식                        │
│ ≡ 5. 가슴·삼두 저중량    ✎       │
│ ≡ 6. 등·이두 저중량      ✎       │
│ ≡ 7. 하체·어깨 저중량    ✎       │
│ ≡ 8. 휴식                        │
└─────────────────────────────────┘
┌ 가슴·삼두 저중량 ─────────── ✎ ┐
│ ≡ 벤치프레스    목표 [8]~[10]회 │
│ ≡ 인클라인 덤벨 목표 [10]~[12]회│
│ ≡ 딥스(맨몸)    목표 [12]~[15]회│
└─────────────────────────────────┘
```

### 5.4 최고 기록
- 운동별 카드: 종류에 맞는 최고 기록 + 마지막 수행일.
  - 무게: 최고 무게(그때 횟수), 최고 횟수, 최고 추정 1RM
  - 맨몸: 최고 횟수, 최고 추가 무게
  - 유산소: 최장 시간, 최장 거리, 최고 페이스(가장 빠른 평균 페이스, 거리가 있는 기록만)
- 운동을 누르면 날짜별 기록 목록(어느 루틴·강도였는지 표시)과 그래프.
  - 유산소 그래프는 거리, 페이스, 평균 심박수, 케이던스 중 골라서 본다.
  - 무게 운동 그래프는 **추정 1RM**으로 고중량·저중량 기록을 한 줄로 보여준다.
- 저중량 루틴의 운동에는 "추정 1RM의 68%"처럼 참고 비율을 작게 표시한다(자동 계산·채움에는 쓰지 않음). 설정에서 끌 수 있다.
- 워밍업 세트와 디로드 기록은 최고 기록·그래프 계산에서 뺀다.

### 5.5 검색
- 운동 이름과 날짜 메모 내용으로 찾는다. 결과는 날짜 목록이고, 누르면 그 날짜 일지가 열린다.

### 5.6 설정
- 백업 내보내기 / 가져오기, 마지막 백업 시각, 백업 알림 주기(기본 14일)
- 루틴 등록 시 목표 횟수 기본값 (비우면 등록 당일 본 세트 중 가장 적은 횟수를 아래쪽, 거기에 +2를 위쪽으로 [Claude 판단]. 예: 8,8,7회 → 7~9회)
- 디로드: 주기(기본 4바퀴), 세트 비율(기본 50%), 무게 감소(기본 0%, 선택 10% 등)
- 저중량 참고 비율 표시 켜기/끄기

### 5.7 홈 화면 추가 안내
- 홈 화면에서 실행된 상태가 아니면(standalone 아님) iOS 설치 방법(공유 → 홈 화면에 추가)을 안내한다.
- `navigator.storage.persist()`를 요청한다.

## 6. 동작 규칙

### 6.1 운동
- 유산소 기록 칸: **시간**(필수), **거리**(km), **평균·최고 심박수**(bpm), **평균 케이던스**(spm, 분당 걸음 수). 시간 외에는 모두 선택이다. 값은 애플 피트니스 앱에 나온 숫자를 직접 옮겨 적는다(PWA는 HealthKit에 접근할 수 없음).
- **페이스**(분/km)는 입력하지 않고 시간 ÷ 거리로 자동 계산해 보여준다. 거리가 없으면 표시하지 않는다. [Claude 판단: 입력 칸을 줄이고 시간·거리와 숫자가 어긋나지 않게 하기 위해]
- 처음 이름을 입력할 때 종류(무게 / 맨몸 / 유산소), 증가 단위(무게 운동: 기본 2.5kg), 주 부위·보조 부위를 정한다. 나중에 고칠 수 있다.
- 운동별 고정 메모(기구 세팅 등)는 일지에서 그 운동에 항상 보인다.

### 6.2 지난번 기록 채우기
- 루틴을 고르면 루틴의 운동마다 **같은 루틴으로 했던 가장 최근 일지(디로드 제외)**에서 그 운동의 세트(워밍업 포함)를 복사한다.
- 해당 루틴 기록이 없으면 그 운동의 가장 최근 기록에서, 그것도 없으면 빈 세트 하나를 둔다.
- 고중량·저중량은 서로 다른 루틴이므로 각자의 기록에서 채운다. 저중량 무게를 1RM 비율로 자동 계산하지 않는다.

### 6.3 무게 올릴 차례 (더블 프로그레션)
- 기준: 같은 루틴의 지난번 기록, 워밍업 제외 모든 세트, 루틴에 정한 목표 횟수 범위.
- 모든 본 세트가 **범위 위쪽 숫자 이상**이면 "⬆ 무게 올릴 차례"를 표시하고, 무게를 `+증가 단위`, 횟수를 범위 아래쪽 숫자로 미리 채운다.
- 아니면 같은 무게와 지난번 횟수를 그대로 채운다(사용자가 `+1회`로 올림).
- 맨몸 운동: 위쪽 숫자를 채웠으면 "추가 무게 고려"만 표시하고 숫자는 그대로 둔다.
- 유산소: 추천하지 않는다.
- 세트마다 무게가 다르면 판단과 무게 증가를 세트별로 적용한다. [Claude 판단]
- 추천은 미리 채우기일 뿐이며 사용자가 고치면 그대로 저장한다.

### 6.4 루틴 순서와 다음 차례 [세부 규칙은 Claude 판단]
- 차례·바퀴·디로드 상태는 **저장하지 않고 일지 기록에서 매번 계산**한다. 지난 날짜를 고치거나 채워 넣어도 자동으로 맞춰진다.
- 다음 차례 = **날짜가 가장 늦은** 루틴 기록(휴식 포함)의 다음 항목. 저장한 순서가 아니라 날짜 기준이다.
- 휴식 항목: 휴식 차례인 날에 일지를 쓰지 않고 하루가 지나면 휴식한 것으로 **간주**하고 다음 항목으로 넘어간다. 휴식 기록을 따로 만들지는 않고, 달력에는 그 날을 흐리게 "휴식"으로 표시한다. 휴식을 직접 기록해도 된다.
- 운동 차례인 날을 기록 없이 넘기면 차례는 그 루틴에 그대로 머문다(자동으로 건너뛰지 않음).
- 지난 날짜를 열면 **그 날짜 이전 기록 기준**의 다음 차례를 기본 선택하고, "지난번 기록"도 그 날짜 이전에서 찾는다.
- **건너뛰기**: 다음 차례가 아닌 루틴을 고르면, 그다음 차례는 고른 루틴의 다음 항목부터 이어진다.
- **바퀴**: 기록된 루틴 항목의 순서 번호가 바로 앞 기록보다 작거나 같아지면(목록이 한 바퀴 돌아감) 한 바퀴 완료로 센다. 건너뛰기로 1번을 지나쳐도 이 규칙으로 센다.

### 6.5 디로드
- **A. 주기**: 마지막 디로드 이후 설정한 바퀴 수(기본 4)를 채우면 달력에 "디로드 차례"를 알린다.
- **B. 정체 신호**: 최근 한 바퀴 안에서 **정체 운동이 3개 이상**이면 "조금 일찍 디로드해도 좋겠다"를 알린다. 정체 운동 = 같은 루틴에서 같은 무게로 3번 연속 했는데 모든 본 세트의 위쪽 숫자를 못 채운 운동.
- **C. 직접 켜기**: 일지 모달 또는 달력에서 언제든 디로드를 켜고 끈다.
- 디로드는 **한 바퀴 동안** 유지된다: 시작한 항목에서 출발해 같은 항목 차례가 다시 올 때 자동으로 꺼진다. [Claude 판단]
- 주기 카운트는 **디로드가 끝난 시점**부터 다시 센다. 중간에 직접 끈 디로드도 디로드를 한 것으로 본다. [Claude 판단]
- 정체 신호의 "최근 한 바퀴"는 달력 8일이 아니라 **최근 기록된 루틴 항목 한 바퀴**(목록 길이만큼)로 본다. [Claude 판단]
- 디로드 중 채우기: 세트 수 × 세트 비율(올림), 무게 × (1 − 무게 감소)를 증가 단위로 반올림.
- 디로드 기록은 최고 기록, 그래프, 무게 올릴 차례, 정체 판단, 지난번 기록 채우기에서 뺀다. 루틴 순서는 평소대로 이어진다.

### 6.6 추정 1RM
- Epley 공식 `무게 × (1 + 횟수 / 30)`, 1~12회 세트에만 적용한다. 그 운동의 최고값을 그날 값으로 쓴다.
- 무게 운동에만 계산한다(맨몸 운동은 체중 기록이 없으므로 제외).

### 6.7 신기록 표시
- 저장할 때 5.4의 최고 기록 중 하나라도 넘으면 해당 운동에 🏆를 표시한다. 워밍업·디로드 제외.

### 6.8 자동완성
- 운동 이름 입력 시 기존 운동 이름을 부분 일치로 보여준다(최근 사용 순). 없는 이름이면 새 운동을 만든다(6.1).

### 6.9 백업
- 내보내기: 전체 데이터를 `schemaVersion`이 들어간 JSON 한 파일로. iOS에서는 공유 시트(`navigator.share` 파일 공유)로 파일 앱·iCloud Drive에 저장, 안 되면 다운로드.
- 가져오기 [Claude 판단]: 앱을 다시 설치하면 id가 새로 생기므로 id만으로 합치지 않는다.
  - 운동은 **같은 이름이면 같은 운동**으로 합치고, 기록이 가리키는 운동 id를 바꿔 준다(최고 기록이 둘로 나뉘지 않게).
  - 루틴도 같은 이름이면 합친다.
  - 일지는 날짜가 고유하므로 **같은 날짜**를 충돌로 본다. 가져오기 전에 "새로 추가 N일, 겹치는 날짜 M일"을 보여주고, 겹치는 날짜를 **기존 유지 / 백업으로 바꾸기** 중 고르게 한다. 조용히 지우거나 중복으로 만들지 않는다.
  - 같은 id는 `updatedAt`이 최신인 쪽을 쓴다.
- 내보내기 성공 시 마지막 백업 시각을 갱신한다.

## 7. 데이터 구조 (초안)

공통 필드(모든 레코드): `id`(UUID), `createdAt`, `updatedAt`, `deletedAt?`(삭제는 표시만). DB와 백업 파일에 `schemaVersion`.

- **Exercise**: `name`, `type`('weight' | 'bodyweight' | 'cardio'), `incrementKg`, `primaryMuscles[]`, `secondaryMuscles[]`, `note`
- **Routine**: `name`, `kind`('workout' | 'rest'), `intensity`('heavy' | 'light' | null, 저중량 참고 비율 표시와 기록 목록의 강도 표시에 씀 [Claude 판단]), `order`, `items[]` = { `exerciseId`, `order`, `targetRepsMin`, `targetRepsMax` }
- **Entry** (날짜당 1개): `date`('YYYY-MM-DD', 고유), `routineId?`, `isDeload`, `memo`, `exercises[]` = { `exerciseId`, `order`, `sets[]` }
  - set = { `isWarmup`, `weightKg?`, `reps?`, `addedWeightKg?`, `durationSec?`, `distanceKm?`, `avgHeartRate?`, `maxHeartRate?`, `avgCadence?` } (페이스는 저장하지 않고 계산)
- **Settings** (단일): 5.6 항목 + `lastBackupAt`, `lastDeloadCycle` 등 계산에 필요한 상태

**저장 계층**: 화면은 IndexedDB를 직접 쓰지 않고 저장 모듈(repository) 함수만 호출한다. 나중에 서버 동기화는 이 모듈에 붙인다.

## 8. 기술 결정

- Vite + React + TypeScript
- Dexie (IndexedDB)
- vite-plugin-pwa (매니페스트, 오프라인 캐시, iOS 아이콘)
- GitHub Pages (개인 계정 crebits) 배포
- **공통 부분 분리**: 루틴 순환(다음 차례·바퀴), 지난번 기록 채우기, 목표 범위 기반 "올릴 차례" 판단, 디로드 주기 계산은 운동 용어(세트·kg)에 묶이지 않은 순수 함수 모듈로 분리한다. 운동 쪽은 이 모듈에 "기록 항목과 비교 방법"을 넘겨 쓴다. 나중에 악기 연습·러닝·공부 같은 다른 영역에 다시 쓰기 위해서다. 단, 1차 화면과 데이터는 운동 전용으로 만들고 범용 설정 기능은 만들지 않는다.
- **나중에 네이티브 앱**: 서비스로 만들 때 같은 React 코드를 Capacitor로 감싸 HealthKit(심박수 등), 휴식 타이머 알림, 애플 워치 문제를 푼다. 이를 위해 브라우저 전용 기능(파일 공유, 저장소 등)은 저장 모듈처럼 한 곳에서 감싸 둔다.
